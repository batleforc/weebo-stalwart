---
title: Reason codes
description: Every code the operator puts on a condition, an Event or an admission denial.
---

Every condition, Event and admission denial the operator writes carries one
of these codes, never free text: alerts, scripts and `kubectl` filters can
rely on them. The list is generated from the operator's source, so it
matches the installed version.

- **Blocking**: `Ready` turns `False` with this reason, and every failed
  reconcile records a `Warning` Event with it ([Events](/docs/reference/events)).
  An admission webhook denial carries one too (HTTP 403, the code as its
  reason).
- **Advisory**: the CR still works. `Reconciled` is the reason of `Ready: True`; the
  others are a condition of their own (its `type` is the code, its
  `status` `"True"`) or a lifecycle Event.

Every CR's `Ready` reason also labels the reconcile counter
([Metrics & health](/docs/reference/metrics)), so a code can be graphed and
alerted on. To find where one shows up right now:

```bash
kubectl get events -A --field-selector reason=InstanceNotFound
```

| Code | Severity | Shows as | Meaning | What to do |
| --- | --- | --- | --- | --- |
| `Reconciled` | advisory | `Ready: True` | `Ready: True` — the one success reason every reconciler uses. | Nothing |
| `InstanceNotFound` | blocking | `Ready: False`, Event (`Warning`) | `spec.instanceRef` names no `StalwartInstance` nor `StalwartLocalInstance` the operator sees (or, unset, there is none to default to). | [Create the instance](/docs/guides/connect-instance), or fix `instanceRef` |
| `InstanceAmbiguous` | blocking | `Ready: False`, Event (`Warning`) | `spec.instanceRef` is unset and several instances could serve the object. | Set `instanceRef` |
| `InstanceNotAllowed` | blocking | `Ready: False`, Event (`Warning`) | The instance named is out of reach: a `StalwartLocalInstance` of another namespace that doesn't share itself with this one, or outside the namespace the operator is limited to. | Use an instance of the CR's namespace, or have that `StalwartLocalInstance` list it in `sharedWith` |
| `InstanceBindingChanged` | blocking | `Ready: False`, Event (`Warning`) | `spec.instanceRef` by name now designates another instance than the one recorded in `status.instance`: not followed until `spec.instanceRef.kind` says which. | Set `instanceRef.kind` to the instance you want (see [A namespace's own instance](/docs/guides/connect-instance#a-namespaces-own-instance)) |
| `TokenSecretMissing` | blocking | `Ready: False`, Event (`Warning`) | The instance's `tokenSecretRef` Secret, or its key, is missing or not UTF-8. For a `StalwartServiceAccount`, the same of the instance's `appPasswordTokenSecretRef`, or that field unset. | Fix `tokenSecretRef` — or, on a `StalwartServiceAccount`, set the instance's `appPasswordTokenSecretRef` (see [The App Password key](/docs/guides/connect-instance#the-app-password-key)) — or create the Secret (the bootstrap Job writes it on its first run) |
| `TokenSecretNotAllowed` | blocking | `Ready: False`, Event (`Warning`) | The `tokenSecretRef` (or `appPasswordTokenSecretRef`) Secret of a `StalwartLocalInstance` lacks the `instance-token: "true"` label: the operator only reads a Secret that opts in. | Label the Secret (of `tokenSecretRef` or `appPasswordTokenSecretRef`) `stalwart.weebo.io/instance-token: "true"` |
| `InvalidSpec` | blocking | `Ready: False`, Event (`Warning`), admission denial | The instance's spec can't produce a client (e.g. an invalid `url`). Only a change of the CR clears it. | Fix the spec; the message says what's wrong (an alias with an `@`, a Vault target not named `smtp`, `deletionPolicy: Delete` on a domain…) |
| `InstanceUnreachable` | blocking | `Ready: False`, Event (`Warning`) | Stalwart did not answer (network error, timeout, 502/503/504). | Check Stalwart's health and the URL/CA; it's retried automatically |
| `InstanceUnauthorized` | blocking | `Ready: False`, Event (`Warning`) | Stalwart refused the instance's token (401/403). | The API key was revoked or lacks permissions: issue a new one (see [The API key](/docs/guides/connect-instance#the-api-key)) |
| `RemoteError` | blocking | `Ready: False`, Event (`Warning`) | Stalwart answered with an unexpected error. | Read the message; often a value Stalwart's schema refuses (a lowercase `locale`, an unknown top-level domain) |
| `KubernetesApiError` | blocking | `Ready: False`, Event (`Warning`) | A Kubernetes API call of the operator itself failed (reading a CR or a Secret, patching a status, the finalizer) — retried. | Transient; retried automatically |
| `Created` | advisory | Event (`Normal`) | The remote object was created for this CR (Event only). | Nothing |
| `DriftCorrected` | advisory | Event (`Normal`) | Fields of the remote object no longer held their desired value (changed on the remote side) and were put back; the Event names them (Event only). Coming back on every reconcile for the same field, it is a comparison bug, not a drift. | Nothing, unless it names the same field on every reconcile: then Stalwart stores that field differently than it is sent (a comparison bug, report it) |
| `Deleted` | advisory | Event (`Normal`) | The finalizer deleted the remote object of this CR (Event only). | Nothing |
| `Released` | advisory | Event (`Normal`) | The finalizer finished — cleanup done, or the CR force-orphaned (Event only). | Nothing |
| `LeavesWatchScope` | blocking | `Ready: False`, Event (`Warning`) | An update would take a CR still carrying the finalizer out of the operator's label selector (`watch.labelSelector`): refused at admission. | Set the `force-orphan` annotation first, or move the CR to another release's selector and remove its finalizer |
| `NamespaceNotAllowed` | blocking | `Ready: False`, Event (`Warning`), admission denial | No `StalwartNamespacePolicy` rule allows this kind in this namespace for the domains and names it asks for (or a `Deny` rule matches): refused at admission, re-checked before any Stalwart call. | Adjust the [allow-list](/docs/guides/allow-list): kind, domain, and the name and every alias |
| `SecretTargetFailed` | blocking | `Ready: False`, Event (`Warning`), admission denial | A `secretTargets` entry couldn't be written, checked or deleted (refused by its backend, owned by another CR, out of the paths the instance allows). | Check RBAC or Vault access and the target's namespace/name (a Vault target is named `smtp`, without `path`) |
| `RemoteObjectClaimed` | blocking | `Ready: False`, Event (`Warning`) | Another CR already owns the remote object this CR would create (same name on the same Stalwart server): never taken over. | Another CR owns that Stalwart object: rename this one, or delete the other |
| `StalwartObjectAlreadyExists` | blocking | `Ready: False`, Event (`Warning`) | The remote object's name (or one of its addresses) is already taken in Stalwart by an object no CR of this one owns: the operator never adopts by name — `weebo-stalwart-importer` links an existing object to its CR. | The address exists in Stalwart (created by hand or by an OpenID Connect login): link it with the [importer](/docs/guides/migration), or pick another name |
| `UnsupportedStalwartVersion` | blocking | `Ready: False`, Event (`Warning`) | The schema Stalwart serves (`GET /api/schema`, its hash) is not one this operator release was tested against: no write is attempted until a release supports it. | Run the Stalwart version this operator release supports, or upgrade the operator |
| `DomainNotFound` | blocking | `Ready: False`, Event (`Warning`) | `spec.domainRef` names no `StalwartDomain`. | Create the `StalwartDomain`, or fix `domainRef` |
| `DomainNotReady` | blocking | `Ready: False`, Event (`Warning`) | The `StalwartDomain` of `spec.domainRef` is not `Ready` (or is bound to another instance): retried once it is. | Fix the domain first; this one follows on its own |
| `AccountNotFound` | blocking | `Ready: False`, Event (`Warning`) | An `accountRef` names no `StalwartAccount` of this namespace, or one without a confirmed `status.address` yet. | Create the `StalwartAccount` in this namespace, or wait for it to be `Ready` |
| `ObjectIsLinked` | blocking | `Ready: False`, Event (`Warning`) | Stalwart refused to delete the remote object: other objects still use it (`objectIsLinked`). Retried, never forced. | Remove what still uses the object (a group's members); the deletion is retried |
