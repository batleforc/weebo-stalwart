- **API version:** `stalwart.weebo.io/v1alpha1`
- **Scope:** Namespaced
- **Short names:** none
- **Guide:** [Service accounts](/docs/guides/service-accounts)

A sending account of an application (`x:Account` of type `User`,
authenticating with an App Password): the operator creates the account
without any password, has Stalwart generate an App Password for it
(granting `authenticate` and `emailSend` only) with the instance's
`appPasswordTokenSecretRef` key, and writes the SMTP submission settings
to `secretTargets` (`host`, `port`, `security`, `username` — the
address —, `password` — the App Password —, `from`). It logs in over
SMTP submission only: IMAP, POP3 and ManageSieve logins are disabled,
and so is delivery unless `receive` is set. An instance without
`appPasswordTokenSecretRef` fails with `TokenSecretMissing`.

A new App Password replaces the previous one (revoked in the same call;
the account's other App Passwords are left alone) when the annotation
`stalwart.weebo.io/rotate-secret` takes a new value, or when a target
lost it. The account is read by `status.remoteId`, never adopted by
name: an address already taken in Stalwart fails
(`StalwartObjectAlreadyExists`) until `weebo-stalwart-importer` links
it to this CR.

## Example

```yaml
apiVersion: stalwart.weebo.io/v1alpha1
kind: StalwartServiceAccount
metadata:
  name: my-serviceaccount
  namespace: team-a
spec:
  domainRef:
    name: example.internal
  name: forgejo
  aliases:
    - noreply
  secretTargets:
    - name: forgejo-smtp
```

## Spec fields

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `aliases` | `string[]` | no |  | Other local-parts of the account, in the same domain, usable as sender (`from` is the first one). Compared as a set.<br /><br />Constraints: `maxItems: 32` |
| `deletionPolicy` | `string` | no | `"Delete"` | `Delete` (default): deleting the CR deletes the account and the secrets it wrote. `Orphan`: both are left in place.<br /><br />Values: `"Delete"`, `"Orphan"` |
| [`domainRef`](#spec.domainRef) | `object` | yes |  | The `StalwartDomain` (cluster-scoped, by `metadata.name`) the account's address and aliases are in. It must be `Ready` on the same instance. |
| [`instanceRef`](#spec.instanceRef) | `object` | no |  | The `StalwartInstance` (or `StalwartLocalInstance`) the account lives on. Unset: the only `StalwartInstance`, else the only `StalwartLocalInstance` of the namespace. |
| `name` | `string` | no |  | The local-part of the account's address (`<name>@<domain>`), lowercased. Defaults to the CR's `metadata.name`. Changing it moves the address: only applied with the annotation `stalwart.weebo.io/allow-disruptive-update: "true"`. |
| `receive` | `boolean` | no | `false` | Whether mail sent to the account is delivered. `false`: delivery is disabled (a no-reply sender). |
| [`secretTargets`](#spec.secretTargets) | `object[]` | no |  | Where the SMTP settings and the App Password are written. Empty: one Kubernetes `Secret` named after the CR, in its namespace (only when the instance's default backend is `kubernetes`). A Vault target must be named `smtp`, without `path`: it is written to `<pathPrefix>/<namespace>/smtp`, the only path the operator's Vault role may write.<br /><br />Constraints: `maxItems: 8` |

### `spec.instanceRef` [#spec.instanceRef]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `kind` | `string` | no |  | The kind of instance a reference designates.<br /><br />Values: `"Instance"`, `"LocalInstance"` |
| `name` | `string` | yes |  | `metadata.name` of the instance. |
| `namespace` | `string` | no |  | Namespace of a `LocalInstance`. Defaults to this object's own; required on a cluster-scoped object. Another namespace's local instance must share itself with this one (its `sharedWith`). |

**Rules**

- namespace only applies to kind LocalInstance — `!has(self.namespace) || !has(self.kind) || self.kind == 'LocalInstance'`

### `spec.secretTargets[]` [#spec.secretTargets]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `backend` | `string` | no | `"kubernetes"` | `kubernetes` (default) or `vault`. A Vault target reuses the Vault connection (address, mount, auth) the instance configures, which it must then do.<br /><br />Values: `"kubernetes"`, `"vault"` |
| `name` | `string` | yes |  | Kubernetes: the `Secret` name. Vault: names the default path `<pathPrefix>/<namespace>/<name>` when `path` is unset. |
| `namespace` | `string` | no |  | Kubernetes `Secret` namespace (Vault: the namespace segment of the default path). Defaults to the CR's own namespace; required on cluster-scoped CRs. A namespaced CR may only name its own namespace. |
| `path` | `string` | no |  | Vault only: explicit KV v2 path under the instance's mount. It must stay under `<pathPrefix>/<namespace>/` (this object's namespace, or the target's on a cluster-scoped object), unless the instance's `pathGrants` open it to this object. |
