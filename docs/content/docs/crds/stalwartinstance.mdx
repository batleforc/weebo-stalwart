- **API version:** `stalwart.weebo.io/v1alpha1`
- **Scope:** Cluster
- **Short names:** none
- **Guide:** [Connect a Stalwart](/docs/guides/connect-instance)

Connection to one Stalwart server (v0.16). Cluster-scoped: an org-wide
piece of infrastructure, not owned by a namespace (a namespace's own
server is a `StalwartLocalInstance`). `Ready` tells whether the server
answers with the token below and speaks a management schema this
operator release supports.

## Example

```yaml
apiVersion: stalwart.weebo.io/v1alpha1
kind: StalwartInstance
metadata:
  name: my-instance
spec:
  url: http://stalwart.mail.svc:8080
  tokenSecretRef:
    name: stalwart-operator-token
    namespace: mail
    key: token
  appPasswordTokenSecretRef:
    name: stalwart-operator-token
    namespace: mail
    key: appPasswordToken
```

## Spec fields

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| [`appPasswordTokenSecretRef`](#spec.appPasswordTokenSecretRef) | `object` | no |  | A second API key of Stalwart, on the same account as the one above: the one that creates, rotates and revokes the App Passwords of the `StalwartServiceAccount`s (permissions `authenticate`, `impersonate`, `emailSend` and `sysAppPassword*` only). Read on every reconcile of a `StalwartServiceAccount`; unset, those fail with `TokenSecretMissing` (the other kinds don't use it). |
| [`secretStore`](#spec.secretStore) | `object` | no | `{"backend":"kubernetes"}` | Default destination of the secrets the CRs bound to this instance emit, when they list no `secretTargets`. Default: a Kubernetes `Secret`. |
| [`submission`](#spec.submission) | `object` | no | `{"host":"stalwart.mail.svc.cluster.local","port":587,"security":"starttls"}` | The submission service the emitted credentials announce. |
| [`tls`](#spec.tls) | `object` | no | `{"insecureSkipVerify":false}` | TLS verification of the connection above: a private CA to trust (`tls.caSecretRef`), or `tls.insecureSkipVerify`. Default: the platform trust store. |
| [`tokenSecretRef`](#spec.tokenSecretRef) | `object` | yes |  | An API key of Stalwart, sent as `Authorization: Bearer`. Read on every reconcile: rotating it needs no restart. |
| `url` | `string` | yes |  | Base URL of the Stalwart HTTP listener, e.g. `http://stalwart.mail.svc:8080`. Management goes through JMAP, `POST <url>/jmap` (session `GET <url>/jmap/session`); `<url>/api` only serves the schema, whose hash identifies the server's version. |

### `spec.secretStore.vault` [#spec.secretStore.vault]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `address` | `string` | yes |  | Vault server address, e.g. `https://vault.example.com:8200`. |
| [`caSecretRef`](#spec.secretStore.vault.caSecretRef) | `object` | no |  | A private CA to verify Vault's TLS with: a PEM bundle under `key` of a `Secret`, read through the API. Unset: the system trust store. Only consulted for `https://` addresses. |
| `kubernetesAuthMount` | `string` | no | `"kubernetes"` | Mount path of Vault's Kubernetes auth backend. |
| `kubernetesAuthRole` | `string` | yes |  | Vault Kubernetes-auth role the operator authenticates as: its own ServiceAccount token is exchanged for a Vault token through `auth/<kubernetesAuthMount>/login`. |
| `mount` | `string` | yes |  | KV v2 secrets engine mount (e.g. `secret`) credentials are written under. |
| [`pathGrants`](#spec.secretStore.vault.pathGrants) | `object[]` | no |  | Vault paths this instance's CRs may write to outside their namespace's subtree `<pathPrefix>/<namespace>/`, per namespace (`clusterScoped` is refused: every object writing credentials is namespaced). The Vault policy of the operator's role stays the hard bound.<br /><br />Constraints: `maxItems: 32` |
| `pathPrefix` | `string` | no | `"weebo-stalwart"` | Path prefix under `mount`: the default KV path of a target is `<pathPrefix>/<namespace>/<name>`, one secret per target. Empty: `<namespace>/<name>`. An explicit `path` must stay under `<pathPrefix>/<namespace>/` unless `pathGrants` opens it.<br /><br />With an empty prefix, a path holding a value no CR owns (written by another tool) is taken over by the first CR writing it: only the Vault policy of the operator's role then keeps a CR away from such values. Keep a prefix unless that policy is narrowed to the paths the CRs may write. |

**Rules**

- pathGrants name namespaces: every object writing credentials is namespaced, clusterScoped grants never apply — `!has(self.pathGrants) || self.pathGrants.all(g, !has(g.clusterScoped) || !g.clusterScoped)`

### `spec.secretStore.vault.pathGrants[]` [#spec.secretStore.vault.pathGrants]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `clusterScoped` | `boolean` | no |  | The grant opens `paths` to cluster-scoped objects (instead of `namespaces`). |
| `namespaces` | `string[]` | no |  | Namespaces whose objects may write `paths`: exact names, `*`, or a prefix glob such as `team-*`. `team-*` opens the paths to every matching namespace.<br /><br />Constraints: `maxItems: 64` |
| `paths` | `string[]` | yes |  | Path patterns under the mount, compared segment by segment: a literal segment matches itself, `+` exactly one segment, and a last `*` one or more. Each holds at least one literal segment, e.g. `shared/auth`, `+/auth`, `platform/*`. Prefer exact paths where values not written by the operator live: a covered object may take over a value no object owns yet.<br /><br />Constraints: `minItems: 1`, `maxItems: 64` |

**Rules**

- a grant names namespaces or is clusterScoped, not both — `(has(self.namespaces) && size(self.namespaces) > 0) != (has(self.clusterScoped) && self.clusterScoped)`
- `paths[]`: a path pattern has no "." or ".." segment — `!self.matches('(^|/)\\.\\.?(/|$)')`
- `paths[]`: a path pattern has at least one literal segment — `self.matches('(^|/)[^/*+]+(/|$)')`

### `spec.tls` [#spec.tls]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| [`caSecretRef`](#spec.tls.caSecretRef) | `object` | no |  | Optional custom CA certificate to verify the instance's TLS with, read from a Kubernetes `Secret` (the referenced `key` must hold a PEM bundle). Use this to trust a private CA without mounting it into the operator pod — the operator reads the Secret via the API and hands the PEM to its HTTP client. It is added *on top of* the platform trust store, so publicly-signed endpoints keep working. When unset, only the platform trust store (plus the usual `SSL_CERT_FILE`/`SSL_CERT_DIR` env vars) is used. |
| `insecureSkipVerify` | `boolean` | no | `false` | Skip certificate verification entirely — insecure, intended only for throwaway/self-signed instances. Prefer `caSecretRef` below, which trusts a private CA without turning verification off. |
