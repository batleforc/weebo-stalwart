**weebo-stalwart** is a Kubernetes operator for an existing
[Stalwart](https://stalw.art) mail server (v0.16). Instead of clicking
through Stalwart's web admin, you describe mail domains, the accounts your
applications send with, people's mailboxes, groups and mailing lists as
YAML, apply it to your cluster, and the operator makes Stalwart match — and
keeps it that way.

Stalwart itself is not deployed by this operator: keep installing it your
own way, and point the operator at it.

## What it does for you

- **Your YAML is the source of truth.** A change made by hand in Stalwart's
  web admin is put back on the next pass, and nothing is sent to Stalwart
  when it already matches.
- **It never takes over by surprise.** If an address is already used in
  Stalwart by something the operator didn't create — by hand, or by a first
  OpenID Connect login — it reports the clash
  (`StalwartObjectAlreadyExists`) instead of silently adopting it. Existing
  objects are brought in on purpose, with the [importer](/docs/guides/migration).
- **SMTP credentials land in Secrets, not in chat.** An application's
  sending account gets an App Password, written with the submission
  settings to a Kubernetes Secret or Vault, ready to mount, rotated on
  request.
- **People leave without losing mail.** A mailbox is locked
  (`state: Locked`), not deleted: every login, App Passwords included, is
  refused, and the mail stays.
- **Teams stay in their lane.** A namespace allow-list decides which
  namespace may create which kinds, in which domains, under which names —
  checked when you apply, and again before every change.
